  ```rust
  /// Deduplicate the union of lexical and cppcheck findings by
  /// `(canonical_file_path, line, cwe_id)` (D-11). When the same key appears
  /// in both inputs, the surviving entry has its `source` set to
  /// `SastSource::Both` (D-12); the lexical entry's other fields are kept as
  /// the base because lexical findings carry richer component attribution.
  ///
  /// `Path::canonicalize` may fail on relative paths whose target does not
  /// exist; the original path string is used as the key in that case (matches
  /// the `parsers/npm.rs:228` and `parsers/ros.rs:39` pattern).
  pub fn deduplicate_sast_findings(
      lexical: Vec<SastFinding>,
      cppcheck: Vec<SastFinding>,
  ) -> Vec<SastFinding> {
      use std::collections::HashMap;
      let mut deduped: Vec<SastFinding> = Vec::with_capacity(lexical.len() + cppcheck.len());
      let mut seen: HashMap<(String, u32, u32), usize> = HashMap::new();

      for f in lexical {
          let canon = std::path::Path::new(&f.file_path)
              .canonicalize()
              .unwrap_or_else(|_| PathBuf::from(&f.file_path));
          let key = (canon.to_string_lossy().into_owned(), f.line, f.cwe_id);
          seen.insert(key, deduped.len());
          deduped.push(f); // already SastSource::Lexical
      }

      for f in cppcheck {
          let canon = std::path::Path::new(&f.file_path)
              .canonicalize()
              .unwrap_or_else(|_| PathBuf::from(&f.file_path));
          let key = (canon.to_string_lossy().into_owned(), f.line, f.cwe_id);
          if let Some(&idx) = seen.get(&key) {
              // D-12: dual-detected — promote existing lexical entry to Both.
              deduped[idx].source = SastSource::Both;
          } else {
              seen.insert(key, deduped.len());
              deduped.push(f); // already SastSource::Cppcheck
          }
      }

      deduped
  }
  ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sc2sbom internal pipeline → formatters | The merged `sast_findings` vector flows into CycloneDX, console, and static-analysis-report writers. No new boundary; existing serialization paths apply. |
| Path::canonicalize → filesystem | Read-only filesystem call to compute dedup keys. Failure is handled with fallback to the raw string (Pitfall: never `.unwrap()` canonicalize). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-12 | Tampering | Path::canonicalize on attacker-controlled `file_path` from cppcheck XML | mitigate | `unwrap_or_else(|_| PathBuf::from(&f.file_path))` keeps the raw string when canonicalize fails. The path is used only as a HashMap key — no filesystem read/write is performed against it beyond canonicalize itself, which is read-only and follows symlinks within the user's own filesystem permissions. |
| T-14-13 | Information disclosure | `source: SastSource::Both` leakage in serialized output | accept | Per D-14 the `source` field is not serialized in any current output (CycloneDX, console, static-analysis report); this is metadata only until Phase 15 (SARIF). No external surface change. |
| T-14-14 | Repudiation | Loss of cppcheck-side fields (different `component_name`) when promoted to Both | accept | D-12 explicitly states: "The lexical finding's other fields (component attribution) are preserved as the base." This is intentional — lexical scanner has richer per-component attribution because it walks the same `component_dirs` map but maps directly via `(name, ecosystem)` keys. Test `dedup_collision_promotes_lexical_to_both` verifies the base is the lexical entry. |
| T-14-15 | DoS | Pathological dedup with millions of findings | accept | HashMap dedup is O(n) over the union; cppcheck on `--enable=warning,style,security` produces hundreds, not millions, of findings on real-world C codebases. Same complexity profile as the existing lexical scanner. |
