Output: A working AST-primary, lexical-fallback C/C++ scanner integrated into the existing dedup → suppress → writers pipeline. All Wave 0 `#[ignore]` tests from Plan 01 are now de-ignored and pass.
</objective>

ROADMAP success criterion #2 lists 14 CWEs: CWE-78, 119, 120, 122, 125, 134, 190, 295, 319, 362, 367, 369, 416, 476, 732. D-07 explicitly enumerates 11 tractable CWEs for AST argument inspection; D-08 explicitly defers CWE-362, CWE-416, CWE-476 (require dataflow/CFG). The remaining roadmap CWEs not covered by D-07/D-08 are: **CWE-295, CWE-319, CWE-367**.

This plan resolves them as follows:

- **CWE-295 (Improper Certificate Validation):** Added to AST_CWE_RULES via the `AnyCall` ArgCheck against the SSL_CTX_set_verify family. The existing v1.0.17 lexical rules for CWE-295 use ContainsTokens — Phase 20 (ARGVAL-01) will migrate to AST argument-node inspection. For Phase 18 the AST scanner emits CWE-295 on name match, and the lexical fallback still applies for parse-failed files. **Acceptance for Phase 18 = AST rule matches name list and emits SastSource::Ast finding.** Argument-value precision is Phase 20's scope.
- **CWE-319 (Cleartext Transmission):** Added to AST_CWE_RULES via the `ContainsTokens(&["CURLOPT_USE_SSL", "CURLUSESSL_NONE"])` ArgCheck against `curl_easy_setopt`. Mirrors existing v1.0.17 lexical token logic; Phase 20 will replace this with AST `enumerator` node inspection per ARGVAL-01.
- **CWE-367 (TOCTOU race):** **Deferred under D-08** with the same rationale as CWE-362/416/476 — TOCTOU detection requires control-flow analysis between the check call (e.g. `access`, `stat`) and the use call (e.g. `open`, `fopen`) within the same function scope. This is dataflow, not local AST. The lexical fallback's existing CWE-367 rule (paired-call paren scan) remains the source of CWE-367 findings under Phase 18. **The executor MUST add a comment in ast_scanner.rs noting CWE-367 is intentionally absent from AST_CWE_RULES per this plan's D-08 extension.** A follow-up to update CONTEXT.md D-08 and ROADMAP §Phase 18 success criterion #2 (to read "all 14 CWEs detected via AST scanner *or* lexical fallback") is filed as a 18-02-SUMMARY.md action item — Phase 18 does not regress coverage because the lexical fallback continues to detect CWE-367 on every file (the AST scanner only emits on tree-sitter success; lexical runs on tree-sitter failure AND remains available via run_lexical_scanner re-export for the benchmark).

Net: AST_CWE_RULES has 13 distinct CWE IDs (D-07's 11 + CWE-295 + CWE-319). Phase 18 detects all 14 ROADMAP CWEs across the union of AST scanner output and lexical fallback output. CWE-367's AST-native detection is post-v1.0.18 work.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user C/C++ source → tree-sitter parser | Untrusted source files (potentially malformed) are parsed into AST. Parser is C code (tree-sitter-c) compiled into the binary. |
| parsed AST → rule application | AST node text is read via `utf8_text(src)` — bounded slice from the in-memory `Vec<u8>` of file contents. |
| AST scanner output → dedup pipeline | `SastFinding` values flow into existing dedup/suppress/SARIF code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-02-01 | Denial of Service | tree-sitter parsing of pathologically deep/large C source | mitigate | tree-sitter is single-threaded and CPU-bounded by file size. Per-file fallback to lexical scan ensures one bad file does not block the run. `read_to_string` errors return empty Vec (file is skipped). |
| T-18-02-02 | Denial of Service | AST recursion stack overflow on deeply nested source | accept | Standard tree-sitter Rust API performs bounded recursion via `TreeCursor`; the cursor-walk pattern (Pitfall 1) uses iteration over children rather than unbounded recursion. Risk is bounded by file size, same as lexical scanner. |
| T-18-02-03 | Tampering | Crafted C source triggering `has_error()` to silently disable AST scan | accept | This is the intended fallback behavior (AST-04). The lexical scanner handles such files; no privilege escalation, no data exposure. Documented warning logged. |
| T-18-02-04 | Information Disclosure | `eprintln!` warning leaking absolute file paths | accept | Path leak via stderr is consistent with existing scanner warnings (`run_cppcheck_scanner`, `warn_on_walkdir_err`). Tool is run on the developer's own workspace; no PII boundary crossed. |
| T-18-02-05 | Spoofing | `SastSource::Ast` variant misattribution in downstream code | mitigate | Task 1 acceptance proves all `match SastSource` arms remain exhaustive under `cargo build`. The dedup logic treats `Ast` symmetrically with `Lexical` (per Plan 01 Edit C). Tests in suppression_tests.rs and sarif_*.rs exercise the pipeline end-to-end. |
| T-18-02-06 | Elevation of Privilege | Static musl binary loading external grammar file | mitigate | tree-sitter-c's `build.rs` compiles `parser.c` into the static archive at build time (verified in 18-RESEARCH.md). No runtime file-system dependency. DIST-02 acceptance is the CI musl build. |
