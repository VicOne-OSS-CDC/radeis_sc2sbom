# Phase 19: cppcheck-removal — Context

**Gathered:** 2026-05-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Hard-remove cppcheck from the codebase entirely: delete the cppcheck runner, XML parser, CLI arg, FP suppression function, and the `SastSource::Cppcheck` variant. Revise `deduplicate_sast_findings` to merge AST vs Lexical findings (replacing the former AST+cppcheck merge). Delete the Phase 18 benchmark test file. The result is a clean AST-only SAST pipeline with no cppcheck subprocess, no escape hatch, and no dead cppcheck code.

</domain>

<decisions>
## Implementation Decisions

### Cppcheck Removal Strategy

- **D-01:** **Hard remove** — cppcheck is deleted entirely. No opt-in escape hatch, no `--features cppcheck` flag, no `--cppcheck-path` arg retained. Clean break. Phases 21–23 will close the CWE coverage gap (CWE-190, 416, 476, 401, 415, 590) via AST rules.
- **D-02:** Delete `run_cppcheck_scanner()` and `parse_cppcheck_xml()` from `src/vulnerability/cwe_scanner.rs` entirely.
- **D-03:** Delete the `--cppcheck-path` CLI arg from `src/cli.rs` (the `cppcheck_path: Option<PathBuf>` field and its clap annotation). Delete the associated warning in `main.rs` ("--cppcheck-path has no effect without --check-vulnerabilities").
- **D-04:** Remove `run_cppcheck_scanner` and `parse_cppcheck_xml` from the `pub use` re-exports in `src/vulnerability/mod.rs`.

### SastSource Enum

- **D-05:** Delete `SastSource::Cppcheck` — it becomes dead code with no cppcheck runner. No replacement variant needed.
- **D-06:** **Keep `SastSource::Both`** — repurposed to represent a finding detected by BOTH the AST scanner AND the Lexical fallback scanner. This is meaningful provenance: a finding confirmed by two independent methods on the same site.

### deduplicate_sast_findings Revision

- **D-07:** Revise `deduplicate_sast_findings` to merge AST findings with Lexical fallback findings (the two sources that now exist). Same dedup key: `(canonical_file_path, line, cwe_id)`. When the same site appears in both AST and Lexical results, the merged entry gets `SastSource::Both`. Rename parameters from `(lexical, cppcheck)` to `(ast, lexical)` to reflect the new sources.
- **D-08:** `main.rs` pipeline simplifies: `ast_findings → deduplicate(ast, lexical_fallback) → sast_findings`. The `cppcheck_confirmed` BTreeSet and all related code is deleted.

### FP Suppression

- **D-09:** Delete `suppress_lexical_false_positives()` entirely — it relied on `cppcheck_scanned_dirs` and `cppcheck_confirmed` sets that no longer exist. AST scanner is now the authoritative source; no secondary confirmation pass needed.
- **D-10:** Remove `suppress_lexical_false_positives` from the `pub use` export in `src/vulnerability/mod.rs`.

### CLI Output / Messaging

- **D-11:** No scanner announcement printed in default CLI output. The "⚠ cppcheck not found" graceful-degradation message is deleted with the runner. AST scanner runs silently. SARIF output encodes `SastSource::Ast` per finding — that is the scanner provenance record.

### Benchmark

- **D-12:** Delete `tests/benchmark.rs` entirely. The Phase 18 benchmark served its decision purpose (confirmed cppcheck demotion choice). It is not needed for Phase 19 onwards. `docs/BENCHMARK.md` can remain as a historical artifact but is no longer generated by a test.

</decisions>

## Specific Ideas
