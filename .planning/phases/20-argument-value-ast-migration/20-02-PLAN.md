<objective>
Remove the lexical scanner's argument-value detection machinery for CWE-295/319/732 now that Plan 01 has made the AST scanner authoritative. Delete the five (or six — exact count established by grep) `arg_value_contains: Some(...)` `CweRule` entries, the `arg_value_contains` field on the `CweRule` struct, the `paren_args_contain_all` function (now dead code), the call site in `scan_file`, the lexical `test_argval_cwe295/319/732*` test functions, and update the rule-table count assertion test.

Purpose: Eliminates duplicate detection paths (AST + lexical both firing on the same call site) and removes the false-positive-prone lexical implementation. Per D-12 and D-13, the AST scanner is sole authority for these CWEs. Parse-fail files lose detection of these specific patterns, which is acceptable because parse-fail is rare on well-formed C code and the wolfSSL gap was closed in Plan 01 (D-06).

Output: A leaner `cwe_scanner.rs` with a smaller `CweRule` struct, reduced rule table, no dead helper. Full test suite green.
</objective>
