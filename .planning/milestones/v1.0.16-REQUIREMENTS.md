# Requirements: radeis_sc2sbom

**Defined:** 2026-05-09
**Milestone:** v1.0.16 — C/C++ Lexical CWE Scanner
**Core Value:** Accurate, spec-compliant SBOM output that downstream consumers (xZETA, compliance tools) can ingest without errors.

## v1.0.16 Requirements

### Feature Gate

- [x] **GATE-01**: `cargo feature = "internal"` compiles out all CVE vulnerability scanning code when absent
- [x] **GATE-02**: `cargo feature = "internal"` compiles out all CWE enrichment (NVD) code when absent
- [x] **GATE-03**: `cargo feature = "internal"` compiles out all lexical CWE scanner code when absent
- [x] **GATE-04**: Public release binary built without `internal` feature passes `cargo test` with no CVE/CWE functionality present

### Lexical Scanner

- [x] **SCAN-01**: Scanner detects dangerous function calls in .c, .h, .cpp, .hpp, .cc files across component-mapped directories
- [x] **SCAN-02**: Scanner covers all 13 CWEs from the confirmed SEED-001 list (CWE-120, CWE-78, CWE-242, CWE-327, CWE-377, CWE-190, CWE-134, CWE-22, CWE-807, CWE-362, CWE-367, CWE-20, CWE-126, CWE-676)
- [x] **SCAN-03**: CWE-134 (format string) uses format-arg heuristic — flags `printf`/`fprintf`/`syslog` family only when format argument is not a string literal
- [x] **SCAN-04**: Scanner records file path and line number for each finding
- [x] **SCAN-05**: Scanner is scoped to component-mapped C/C++ directories only — does not scan the full source tree

### CycloneDX Output

- [x] **CDX-01**: Each finding emits a CycloneDX 1.5 `vulnerabilities[]` entry with `cwes[]` (integer array), `source.name = "radeis_sc2sbom static analysis"`, and `analysis.state: "in_triage"`
- [x] **CDX-02**: Each vulnerability entry includes `affects[].ref` linking to the owning component's `bom-ref`
- [x] **CDX-03**: File path and line number are stored in `properties` as `sc2sbom:finding:file` and `sc2sbom:finding:line`
- [x] **CDX-04**: SAST findings are emitted in CycloneDX output only — SPDX 2.3 output is unchanged (no native vulnerability model in SPDX 2.3)

### Reporting

- [x] **RPT-01**: Scan produces a separate `_static_analysis.md` report with per-component CWE summary table and file:line findings
- [x] **RPT-02**: Static analysis findings section is integrated into the main markdown scan report alongside CVE findings
- [x] **RPT-03**: CLI prints disclaimer when static analysis runs: "Pattern-based — complex data-flow vulnerabilities not covered"

## Future Requirements

### v1.0.17 — tree-sitter AST Scanner

- **TREE-01**: Upgrade lexical scanner to tree-sitter AST — exact call-site detection (not token match), zero external dependency
- **TREE-02**: Add CWE-476 (NULL pointer dereference) via unchecked `malloc`/`calloc` return-value detection within function scope
- **TREE-03**: Add CWE-252 (unchecked return value) via AST return-value assignment inspection
- **TREE-04**: Add CWE-416 (use-after-free) via intra-function `free()` + dereference pattern
- **TREE-05**: Add CWE-415 (double free) via intra-function `free()` + `free()` on same identifier
- **TREE-06**: Reduce CWE-134 false positive rate via exact argument-type inspection (vs. next-token heuristic)

### Future — External Tool Integration

- **EXT-01**: Optional cppcheck subprocess integration (`--with-cppcheck`) for ~48 CWEs with dataflow analysis (Linux/macOS/Windows — requires user install)
- **EXT-02**: Custom YAML rule file (`--cwe-rules`) to extend built-in pattern table with project-specific banned functions

## Out of Scope

| Feature | Reason |
|---------|--------|
| CWE-401 (memory leak) | Requires control-flow graph — lexical FP rate >50%; deferred indefinitely |
| CWE-457 (uninitialized variable) | Requires liveness analysis — not tractable without full dataflow |
| CWE-415/416 (double free / use-after-free) | Require dataflow — deferred to v1.0.17 tree-sitter implementation |
| CWE-476 (null pointer dereference) | Requires dataflow — deferred to v1.0.17 tree-sitter implementation |
| SARIF output | Differentiator; not required for xZETA ingestion — future scope |
| Suppress-list / `sc2sbom-nocheck` annotations | Mature SAST feature; out of scope for SBOM enrichment layer |
| Full dataflow / taint analysis | SAST scope, not SBOM scope — tool boundary is lexical presence detection |
| SPDX 2.3 CWE findings output | No native vulnerability model in SPDX 2.3 spec |
| cppcheck / Flawfinder bundling | External C++ / Python tools cannot be compiled into a static Rust binary |
