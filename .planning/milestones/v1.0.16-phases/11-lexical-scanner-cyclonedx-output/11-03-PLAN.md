<objective>
Extend the CycloneDX formatter so SAST findings are emitted as `vulnerabilities[]` entries per CDX-01..CDX-04, and wire `run_lexical_scanner` into `main.rs` at the D-04 invocation point.

This plan does three things:
1. Extend the `CycloneDXVulnerability` struct (add `analysis`, `properties`) and make `CycloneDXVulnerabilitySource.url` optional (Pitfalls 1 & 2 from 11-RESEARCH.md). Update the two existing CVE construction sites accordingly.
2. Add a new `build_sast_vulnerabilities` function and call it from `convert_to_cyclonedx`, threading `sast_findings: &[SastFinding]` through the formatter's public API. Use cfg-split signatures (option b) so non-internal builds still compile (per 11-RESEARCH.md "Code Examples" section).
3. Invoke `run_lexical_scanner` inside the existing `#[cfg(feature = "internal")]` block in `main.rs`, after `enrich_cwe_ids`, and pass `&sast_findings` to `save_cyclonedx_json` and `print_cyclonedx_json`.

SPDX 2.3 output is intentionally untouched (CDX-04). Plan 04 validates this with a byte-for-byte regression test.

Purpose: Realize CDX-01..CDX-04 — get SAST findings into CycloneDX output and wire the runtime.
Output: A CycloneDX 1.5 document that includes one `vulnerabilities[]` entry per scanner finding, linked to its component via `affects[].ref`, with `cwes`, `analysis.state`, and `properties` populated.
</objective>
