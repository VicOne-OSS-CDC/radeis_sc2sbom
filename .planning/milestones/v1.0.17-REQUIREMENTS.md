# Requirements: radeis_sc2sbom

**Defined:** 2026-05-10
**Core Value:** Accurate, spec-compliant SBOM output that downstream consumers (xZETA, compliance tools) can ingest without errors.

## v1.0.17 Requirements

Requirements for milestone v1.0.17 — Advanced C/C++ SAST Scanner.

### Argument-Value Matching (Track B)

- [x] **ARGVAL-01**: Scanner detects CWE-295 when `SSL_CTX_set_verify`, `SSL_set_verify`, or `wolfSSL_CTX_set_verify` is called with `SSL_VERIFY_NONE` as an argument
- [x] **ARGVAL-02**: Scanner detects CWE-319 when `curl_easy_setopt` is called with `CURLOPT_USE_SSL` + `CURLUSESSL_NONE`, `CURLOPT_SSL_VERIFYPEER` (value 0), or `CURLOPT_SSL_VERIFYHOST` (value 0 or 1)
- [x] **ARGVAL-03**: Scanner detects CWE-732 via `umask` calls and `SetSecurityDescriptorDacl` with permissive DACL argument
- [x] **ARGVAL-04**: Scanner detects CWE-369 when a literal `/0` or `%0` constant is found in a division expression
- [x] **ARGVAL-05**: `CweRule` struct supports optional `arg_value_contains` field; match fires only when paren-bound argument list contains the specified token(s)

### cppcheck Subprocess (Track A)

- [x] **CPPCHECK-01**: Scanner invokes `cppcheck --xml --enable=warning,style,security` on component-mapped C/C++ dirs when cppcheck is on PATH
- [x] **CPPCHECK-02**: cppcheck XML output is parsed and cppcheck IDs are mapped to CWE IDs; findings are emitted as `SastFinding` entries through the existing CycloneDX pipeline
- [x] **CPPCHECK-03**: If cppcheck binary is not found on PATH, scanner logs a warning and continues with lexical-only results (no abort)
- [x] **CPPCHECK-04**: `--cppcheck-path` CLI flag allows specifying an explicit cppcheck binary location
- [x] **CPPCHECK-05**: Findings from cppcheck and the lexical scanner are deduplicated by `(file, line, cwe)` tuple — no duplicate entries in output

### SARIF Output

- [x] **SARIF-01**: All `SastFinding` entries (lexical + cppcheck) are written to a `_static_analysis.sarif` file alongside the existing `_static_analysis.md` report
- [x] **SARIF-02**: `--sarif-output` CLI flag allows specifying the SARIF output file path
- [x] **SARIF-03**: SARIF output includes a `rules[]` section where each detected CWE maps to a rule entry with `id`, `name`, and `helpUri` pointing to CWE.mitre.org

## Future Requirements

### Expanded cppcheck coverage

- **CPPCHECK-F1**: Suppress-list support — user-configurable file to silence known FP findings from cppcheck
- **CPPCHECK-F2**: CI timing annotation — log per-component cppcheck duration so users can evaluate performance impact

### Dataflow-backed CWEs

- **DATAFLOW-F1**: CWE-401 (memory leak) — requires control-flow graph; deferred
- **DATAFLOW-F2**: CWE-415/416 (double free / use-after-free) — requires dataflow; deferred
- **DATAFLOW-F3**: CWE-476 (null pointer dereference) — requires dataflow; deferred

## Out of Scope

| Feature | Reason |
|---------|--------|
| CWE-457 (uninitialized variable) | Requires liveness analysis — lexical FP rate unacceptable |
| SARIF output from cppcheck natively piped | cppcheck SARIF format differs from our schema; normalize through SastFinding instead |
| Full Makefile variable expansion | Complexity vs. value tradeoff; emit NOASSERTION instead |
| License detection from source headers | Future scope |
| SPDX 2.3 vulnerability output | No native model in spec |
