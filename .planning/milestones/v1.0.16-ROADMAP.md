## Phase Details

### Phase 10: Internal Feature Gate
**Goal**: CVE scanning (OSV API), CWE enrichment (NVD API), and the lexical CWE scanner all gate behind `cargo feature = "internal"` — the default build compiles none of this code, enabling safe open-source distribution without a strip script
**Depends on**: Phase 9
**Requirements**: GATE-01, GATE-02, GATE-03, GATE-04
**Success Criteria** (what must be TRUE):
  1. `cargo build --release` (no feature flags) produces a binary where all CVE scanning code is absent — the binary cannot call OSV API or NVD API paths
  2. `cargo build --release` (no feature flags) produces a binary where the lexical CWE scanner code is absent — no dangerous-function rule table or scanner invocation is reachable
  3. `cargo build --release --features internal` produces a binary with full CVE + CWE enrichment + lexical scanner functionality intact
  4. `cargo test` passes without the `internal` feature — no test references or stubs for CVE/CWE/scanner code compile without the flag
**Plans**: 4 plans
- [x] 10-01-PLAN.md — Cargo feature + module-level gates (Cargo.toml, lib.rs, main.rs, models/mod.rs)
- [x] 10-02-PLAN.md — Dependency.vulnerabilities field gate + 38 src construction-site migrations
- [x] 10-03-PLAN.md — CLI args/enums + formatter (cyclonedx/spdx/console) gating
- [x] 10-04-PLAN.md — cwe_scanner.rs stub + test gating/migration + CI workflow + strip script comment

### Phase 11: Lexical Scanner + CycloneDX Output
**Goal**: Users running the tool with `--features internal` against a C/C++ project receive CWE findings in CycloneDX 1.5 output — each dangerous-function call site is detected by file, line, and CWE ID, linked to its owning component via bom-ref, and marked `in_triage`
**Depends on**: Phase 10
**Requirements**: SCAN-01, SCAN-02, SCAN-03, SCAN-04, SCAN-05, CDX-01, CDX-02, CDX-03, CDX-04
**Success Criteria** (what must be TRUE):
  1. Running the tool against a C/C++ source tree with `--features internal` produces at least one CWE finding per triggered rule from the confirmed 13-CWE list (CWE-120, CWE-78, CWE-242, CWE-327, CWE-377, CWE-190, CWE-134, CWE-22, CWE-807, CWE-362, CWE-367, CWE-20, CWE-126, CWE-676)
  2. CWE-134 findings fire only when the format argument to `printf`/`fprintf`/`syslog` family calls is not a string literal — calls with hardcoded format strings produce no finding
  3. Findings reference only files inside component-mapped C/C++ directories — source files outside those directories are not scanned
  4. Each finding records the file path and line number of the dangerous call site
  5. CycloneDX output contains a `vulnerabilities[]` entry per finding with `cwes[]` integer array, `source.name = "radeis_sc2sbom static analysis"`, `analysis.state: "in_triage"`, `affects[].ref` to the owning component bom-ref, and `properties` entries for `sc2sbom:finding:file` and `sc2sbom:finding:line`; SPDX 2.3 output is byte-for-byte unchanged
**Plans**: 4 plans
**UI hint**: no

Plans:
- [x] 11-01-PLAN.md — ScanContext.component_dirs field + populate at six C/C++ parser call sites in scan_directory (SCAN-05 foundation)
- [x] 11-02-PLAN.md — Lexical scanner: SastFinding struct, 13-CWE static rule table, paren-bound word-boundary matcher, CWE-134 format-arg heuristic, run_lexical_scanner entry point (SCAN-01..05)
- [x] 11-03-PLAN.md — Extend CycloneDX structs (analysis + properties + Optional source.url), build_sast_vulnerabilities, thread sast_findings through formatter signatures, wire run_lexical_scanner into main.rs after enrich_cwe_ids (CDX-01..04)
- [x] 11-04-PLAN.md — Tests: cwe_scanner unit tests + C fixtures + CycloneDX SAST integration tests + SPDX byte-for-byte regression test

### Phase 12: Static Analysis Report
**Goal**: Scanner findings are surfaced in a dedicated `_static_analysis.md` file, integrated into the main scan report, and the CLI notifies users that the scan is pattern-based — completing the user-facing surface area of the lexical scanner feature
**Depends on**: Phase 11
**Requirements**: RPT-01, RPT-02, RPT-03
**Success Criteria** (what must be TRUE):
  1. A `_static_analysis.md` file is written alongside the scan output containing a per-component CWE summary table (component name, CWE IDs triggered, finding count) and a file:line findings list
  2. The main `_report.md` scan report includes a "Static Analysis Findings" section that integrates the per-component CWE summary — CVE findings section is unchanged
  3. When static analysis runs, CLI stdout includes the disclaimer: "Pattern-based — complex data-flow vulnerabilities not covered"
**Plans**: 3 plans
- [x] 12-01-PLAN.md — Test scaffolding (RED): sast_report_tests.rs with 5 #[test] functions encoding D-01..D-11
- [x] 12-02-PLAN.md — save_static_analysis_report() in console.rs + mod.rs re-export + main.rs call sites (RPT-01, RPT-03)
- [x] 12-03-PLAN.md — Inject "Static Analysis Findings" section into save_console_report() + thread sast_findings through main.rs (RPT-02)
