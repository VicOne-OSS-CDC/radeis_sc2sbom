# Quick Task 260510-2a4: Fix component-mapping inflation in lexical scanner

## One-liner

Added `resolve_component_dir` helper and updated all 6 C/C++ build-system insertion sites to skip external deps with no matching vendored subdir — eliminating 25x inflation from manifest-parent fallback.

## What Changed

### Task 1 — resolve_component_dir helper + 6 insertion sites (commit 56eacd8)

**`src/scanner/mod.rs`**
- Added `pub fn resolve_component_dir(parent: &Path, name: &str) -> Option<PathBuf>` at ~line 409
- Resolution strategy (in order): exact name match, `lib`-prefix match, case-insensitive subdir scan
- Returns `None` when no matching subdir found
- All 6 C/C++ manifest insertion sites (CMakeLists.txt, .cmake, .pc, configure.ac, Makefile.am, additional cmake/makefile arm) updated from `or_insert_with(|| parent.to_path_buf())` to `if let Some(dir) = resolve_component_dir(parent, &dep.name) { component_dirs.entry(...).or_insert(dir); }`
- Vendored 3rd_party insertion site (~line 1054) left untouched — already derives path from `dep.source_file`

### Task 2 — regression tests (commit 8739e9e)

**`tests/scanner_tests/vendor_tests.rs`**
- `test_resolve_component_dir_present` — verifies a dep with a matching subdir returns `Some(path)`
- `test_resolve_component_dir_absent` — verifies a dep with no matching subdir returns `None`
- Both tests pass

## Result

Before: 25 external curl deps all mapped to curl's root dir → 26,954 inflated findings (same 264 files × 25 components).
After: External deps with no vendored subdir are skipped → 0 findings for curl (correct — none of curl's deps are vendored in the repo).

## Deviations

- `pub(crate)` promoted to `pub` for `resolve_component_dir` — required for integration tests in separate crate to call the helper directly; idiomatic Rust pattern.
