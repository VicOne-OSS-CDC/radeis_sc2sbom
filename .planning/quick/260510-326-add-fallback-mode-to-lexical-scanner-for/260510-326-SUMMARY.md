# Quick Task 260510-326: Add fallback mode to lexical scanner for standalone C projects

## One-liner

Added `has_c_cpp_files` helper and a fallback block in `main.rs` so manifest-free C repos (like the Juliet test suite) get lexically scanned via a synthetic project-root component entry.

## What Changed

### Task 1 — has_c_cpp_files helper (commit 60985ff)

**`src/vulnerability/cwe_scanner.rs`**
- Added `pub fn has_c_cpp_files(root: &Path, max_depth: usize) -> bool`
- Shallow WalkDir reusing existing `is_c_cpp_source` predicate; returns true on first hit
- 3 unit tests: C file present → true, empty dir → false, non-C file only → false

**`src/vulnerability/mod.rs`**
- Re-exported `has_c_cpp_files` under `#[cfg(feature = "internal")]`

### Task 2 — Fallback block in main.rs (commit 77047bc)

**`src/main.rs`**
- Changed `let component_dirs` to `let mut component_dirs`
- Added fallback block inside `#[cfg(feature = "internal")]`: if `component_dirs.is_empty() && has_c_cpp_files(&args.path, 3)`, inserts synthetic `(project_name, "C/C++") -> args.path` entry
- Project name derived from last path component of `args.path`
- Fallback never touches SBOM output — internal scanner path only

## Result

Before: Juliet test suite (54,484 C files, no manifests) → 0 findings
After: 181,062 findings across 11 CWEs (CWE-20/22/78/120/126/134/190/242/362/367/377/676/807)

- Added `has_c_cpp_files` re-export to `mod.rs` (not in original plan) — required for build to compile; executor auto-fix (Rule 3).
